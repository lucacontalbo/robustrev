\section{Introduction}
\label{sec:intro}

Large language models (LLMs) are increasingly used as natural-language (NL) interfaces for querying tabular data, making Table Question Answering (Table QA) a natural testbed for evidence retrieval, numerical operation, and analytical reasoning over structured information. Yet most evaluations assume that structure is \emph{explicit}, as in clean relational schemas\mpaga{, and that the relevant evidence is contained in a single table or connected through predefined database relations}. Many real spreadsheets and reports are instead \emph{non-relational}: the structure needed to answer a question is encoded in the presentation itself, through hierarchical headers, merged cells, blank regions, unit conventions, noisy entries, or implicit dependencies between cells \mpaga{and tables}~\cite{1.10}.

This is a blind spot in current Table QA evaluation. A model may answer correctly over a clean relational table yet fail when the same latent evidence is rendered as a non-relational view, and this gap widens sharply once the evidence is distributed across multiple tables (\autoref{fig:nonrelhurts}; \S\ref{app:generating_non_rel}). \mpaga{Addressing this gap requires a tool that can generate, on demand, reliably supervised QA data over multiple non-relational tables, tailored to different domains, layouts, perturbations, and evidence-distribution patterns.}

\mpaga{Existing resources do not provide this flexibility. First, manually curated benchmarks, whether relational or non-relational, contain realistic tables (\S\ref{sec:rw}), but they are fixed in their domains, layouts, question distributions, and rarely target genuinely multi-table reasoning~\cite{1.26,1.16}. Extending them requires the joint manual design and validation of tables, questions, units, missing values, perturbations, and gold answers, making them costly to scale, difficult to adapt to new evaluation scenarios, and potentially exposed to contamination in recent LLMs~\cite{datacontamination}. Second, automatic generators provide scalable and verifiable supervision, but existing approaches are designed around relational databases. They derive questions from explicit schemas, existing relations, and predefined join paths, thereby constraining both the space of generated questions and the ways in which evidence can be organized across tables~\cite{PapicchioPC23,5.5,5.8}.}

A useful benchmark must further vary layouts, surface forms, and unit conventions independently while preserving the gold answer.

\mpaga{A natural workaround is to adapt either type of resource by converting manually curated or automatically generated relational tables into non-relational views. This approach, however, is insufficient for both practical and conceptual reasons. Practically, only a small fraction of Spider~\cite{1.6}, BIRD~\cite{1.20}, and BEAVER~\cite{1.30} tables can be transformed into realistic dense, hierarchical layouts without creating invalid cells, and these constraints become even stricter when multiple tables must jointly support a question (\S\ref{app:generating_non_rel}). Conceptually, relational sources do not fully capture the reasoning patterns arising in non-relational multi-table settings. We identify two main types: \emph{parallel}, which combines independent evidence across tables, and \emph{sequential}, which uses information from one table to retrieve evidence from another. The latter only loosely resembles a join chain, as links are implicit, while the former has no direct relational counterpart because tables may share neither keys nor schema (\autoref{fig:questiontypes}). These limitations motivate generating adaptable and verifiable non-relational multi-table scenarios directly.}

To address these limitations, we introduce \name, a from-scratch framework for generating automatically verifiable QA benchmarks over multiple non-relational tables. Given a target domain and lightweight controls such as attribute cardinalities and table count, \name uses an LLM to define a domain-specific schema, instantiates a \emph{latent relational source}, derives executable SQL programs with scalar answers, and verbalizes them into NL questions. It then renders perturbed \emph{non-relational views}, combining established Table QA perturbations~\cite{2.4,2.5,2.6,2.8} with pivots, hierarchical headers, merged cells, layout changes, and unit conversions, while controlling evidence distribution for \emph{parallel} and \emph{sequential} reasoning.


The core idea is to \emph{decouple supervision from presentation}: answers are computed and verified on the latent relational source, while the model sees only perturbed non-relational views. This allows \name to vary reasoning structure, perturbations, answer distributions, and scale to arbitrarily many tables without altering the gold answers.

We evaluate \name on financial and environmental scenarios with up to 20 parallel and 5 sequentially connected tables per question, using \texttt{gpt-5-mini} and Qwen-family models. Accuracy drops by 25--40 points as the number of tables grows; in the hardest settings it remains slightly above 60\% for parallel questions and often below 50\% for sequential ones, while unit heterogeneity compounds these drops by up to 50 points with a strong domain dependence. Beyond evaluation, \name is also useful as a source of supervision: fine-tuning on \name-generated data improves GRI-QA~\cite{1.16} performance over the non-finetuned Qwen baseline, especially when the generated data match the target domain.

In summary, our contributions are:
(i) we introduce \name, a from-scratch generator for automatically verifiable numerical QA over multiple non-relational tables;
(ii) we define two controllable multi-table reasoning regimes, parallel and sequential, together with answer-preserving structural, cell-level, and unit-based perturbations;
(iii) we use \name to evaluate recent LLMs in financial and environmental domains, showing that non-relational presentation, unit heterogeneity, and table count substantially degrade performance;
(iv) we publicly release code and generated datasets\footnote{\href{https://anonymous.4open.science/r/Gradino-DBF6/}{Anonymous Github link}}.
